# Versioned bilingual library documentation

Implement the approved same-repository design: independently versioned carddetector and tfmodel documentation, confirmed per-version installation facts, and English/Spanish navigation. Preserve the existing English integration contracts in docs/agents rather than duplicate them into docs/en. Spanish translations live in docs/es with original-content hashes. The website's existing development URLs remain valid.

A release catalog under docs/releases/history/<module>/<version>.json records immutable code source, documentation revision and confirmed destinations. Finalization archives a destination before replacing its latest pointer; subsequent destination publication augments the same identity, never rewrites code identity. Import examples are rendered with the existing validated renderer for that exact version. Pending releases are excluded. Seed only confirmed metadata already present; do not claim a complete historical archive.

The website reads Markdown at the cataloged Git revision as data, never executes old code. Every build renders all catalog entries under en/<module>/<version>/ and es/<module>/<version>/, including raw Markdown. Guides and source links remain pinned. Missing/stale Spanish pages fall back visibly to the same revision's English page. Current English and Spanish development pages remain separately labeled. Preserve existing raw guide URLs. Show module, version and language selectors plus a version-local sidebar. tfmodel explains its pinned detector dependency, independently of the selected detector release.

Historical media links point to the recorded Git revision to avoid claiming current images belong to older releases. Catalog builds fail on missing revisions, malformed/conflicting identities or unsafe paths. Git checkout must include history. Old versions are rebuilt on every deployment; no Pages-state or expiring artifact dependency. Reviewed documentation-only corrections can pin a newer full SHA in documentation_ref, while source remains immutable and the page discloses both. Initial translations are explicitly pinned by a Git content-tree SHA in the catalog, separately from unchanged released English guides. Per-page English hashes gate reuse; trees remain reachable after squash merges when their content is present on main.

Validation covers archive retention/mirror merging, immutable identity checks, old source resolution, stale translation fallback, exact installation versions, version-local links, translated code preservation, generated HTML links and anchors, Python suite and full site build. No Android runtime behavior or publication is changed or invoked.
