# Shared CLI setup

Repository launchers and setup validation are generated by `android-repo-setup`.
Run `sh ./setup.sh` or `setup.bat` for the interactive menu, or append a command.
The cached executable is not added to your global `PATH`; use the launcher prefix
for the commands below, for example `sh ./setup.sh setup check`.

- `bootstrap check` checks the generated launchers and setup workflow.
- `setup check` additionally checks workflow/configuration drift and evaluates Gradle module inventory.
- `bootstrap generate --overwrite` refreshes launchers after intentionally changing `tooling_ref`.

The bootstrap implementation and tests belong to the CLI repository. The generated
PowerShell runtime lives in `.project/setup/bootstrap.ps1`; `.project/setup/cache/`
is ignored. Release pins use checksum-verified binaries. Full commit pins require
Rust/Cargo and use a cached source build. JitPack installs the same pinned source
and delegates module/tag checks to the CLI, preserving project Java setup.

This migration pins an exact CLI source commit so it can be tested before the next
binary release. Gradle plugin versions remain at their existing released pins.
After a CLI release, use Update GitHub workflows to change the pin and regenerate
both workflows and adopted bootstrap files in one reviewable patch.
