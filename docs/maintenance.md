# Maintain the documentation

## Ownership

- Kotlin source and tests define behavior. `docs/agents/` owns consumer contracts and source-derived reference excerpts.
- `IMPORT.md` is generated by existing release tooling from `docs/templates/MODULE_IMPORT.md.template` and independently confirmed `docs/releases/carddetector.json` / `docs/releases/tfmodel.json`; never manually advance versions.
- `app/` owns runnable snippets. `scripts/docs.py` synchronizes the quickstart and image-handoff helper and verifies hashes of every library Kotlin input.
- `docs/overview.md` owns the human landing page. `sites/` renders guides as searchable Starlight HTML and raw Markdown. No essential integration explanation requires leaving the site.
- `docs/screenshots/` owns the reviewed historical still and manifest; the original MP4 remains under `docs/`. Generated site copies are ignored and fully cleared before synchronization.
- Existing module entry paths are preserved as links to canonical guides. `AGENTS.md` is for contributors, not consumer API documentation.

## Local checks

```bash
python3 scripts/module_release.py verify
python3 scripts/docs.py verify
python3 scripts/media.py verify
python3 -m unittest discover -s scripts/tests -v
cd sites
npm ci
npm run check
npm run dev -- --host 0.0.0.0
```

Open `/android.apexfission.carddetector/`. Production build uses the project subpath and validates internal HTML/raw Markdown links, anchors, images, video sources/posters, installation values and required output files. External URL availability is not a build gate. Node 24 and Python 3.12 are used by CI. Locked dependencies keep the site independent from Android runtime dependencies.

When changing public source, review affected contracts first, then run `python3 scripts/docs.py update` from root and inspect the generated diff. The source extractor is a documentation helper, not a Kotlin compiler or ABI compatibility tool. Full-file hashes intentionally require review even if only behavior changes. The reference labels implementation-facing public declarations separately from recommended entry points.

Run `python3 scripts/media.py render`, inspect candidates, `accept` only deliberately, and `compare` to check reproducibility. Normal site/PR jobs only run integrity verification, not baseline updates. See [media policy](screenshots/README.md).

## Android verification

Use JDK 21 for the Gradle daemon, JDK 17 compilation toolchain, and the repository Android SDK (compileSdk 37); read checked-in build files before upgrading.

```bash
./gradlew :carddetector:testDebugUnitTest :app:assembleDebug
./gradlew :carddetector:assembleDebugAndroidTest :app:assembleDebugAndroidTest
./gradlew :carddetector:connectedDebugAndroidTest
./gradlew :app:installDebug
```

Unit tests and compilation do not establish camera/video correctness. Run the catalog's live permission/denial/capture and simulator flows on a compatible device. The app's OCR methods are placeholders. Historical media is never substituted for current-device release evidence.

Install Python tooling before running documentation checks: `python3 -m pip install -r scripts/requirements-publishing.txt`. For the complete release/setup test suite, use `scripts/requirements-setup.txt`.

## GitHub Pages

In repository **Settings → Pages → Build and deployment**, select **GitHub Actions**. The intended URL is `https://lambdawalker.github.io/android.apexfission.carddetector/`. Configure the `github-pages` environment if repository policy requires approval. The workflow cannot enable Pages on behalf of an owner without that setting.

The Documentation workflow validates PRs with read-only repository permissions. On main it checks out current main under a serialized documentation lock, builds, and deploys with Pages/OIDC permissions isolated to the deploy job. A final main-head check skips stale output. Manual dispatch retries only documentation. Completion of either release/finalization workflow also rebuilds from current main, because a bot's metadata commit might not trigger another push workflow. Failed or foreign-repository workflow runs cannot trigger deployment.

The manual Documentation media candidates workflow renders candidate stills and uploads them for inspection; it never accepts them. A site build copies reviewed media and fails on missing, changed, or pointer-only assets. New media does not require a package upload.

## Release preflight

The existing publication preflight now runs the same documentation/site verification on the checked-out immutable package source before upload. Each module’s release metadata is promoted only after its own registry confirmation, and automatic/manual finalization retain their existing lock and 15-minute environment delay. The documentation workflow separately reacts to finalization completion and reads confirmed metadata from current main.

Do not rerun package upload to fix a site failure. Retry Documentation instead. Historical media integrity is checked at release, but the recording is explicitly not current UI verification. If camera/UI behavior changes, perform exact-source device verification before approving that release; no automated current-device screenshot baseline exists in this repository.
